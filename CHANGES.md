# История изменений Ion Pulse

Формат основан на Keep a Changelog. До первого релиза все изменения записываются
в секцию `Unreleased`, а при релизе переносятся под версию и дату.

## Unreleased

### Added

- Added an idempotent baseline seed command for roles, localized categories, and
  an explicitly configured bootstrap administrator.
- Added PostgreSQL integration coverage in CI for author approval and the public
  editorial path from a member draft to a published material.
- Added PostgreSQL integration coverage for fallback to an original publication
  and worker-backed delivery of its saved second-language localization.
- Added PostgreSQL integration coverage for a community report, moderator
  decision, and hiding the reported comment from public readers.
- Added PostgreSQL integration coverage for password recovery, including
  one-time reset links and revoking pre-reset sessions.
- Added a daily PostgreSQL backup service and timer with dump verification,
  retention, and a documented safe restore drill.
- Added a public release smoke-check script for liveness, readiness, and RU/EN
  feed routes through the reverse proxy.

### Fixed

- PostgreSQL integration scenarios now share one event loop and drain the
  translation queue, making them independent of connection-pool and test order.
- Creating or reviewing a content report now returns its target context without
  serializing context fields twice.
- Expanded Alembic's legacy version column during migration `0007` so databases
  created with a 32-character revision field can apply all current migrations.
- The baseline seeder can now explicitly reset an existing bootstrap administrator
  password while continuing to store it only as an Argon2 hash.
- Registration now explicitly loads a new member's roles before returning the
  authenticated response.
- Category seed rollback now preserves categories referenced by publications, so
  a full Alembic reset can complete safely.
- Production configuration now fails fast when debug mode, an HTTP site URL,
  insecure session cookies, or a weak/default session secret is used.

- Создан основной документ продукта и план разработки `PROJECT.md`.
- Создан словарь предметной области `CONTEXT.md`.
- Зафиксированы двуязычная модель публикаций, RBAC, редакционный workflow,
  переводы, еженедельный журнал и дайджест.
- Создан новый каркас FastAPI с версионированным API.
- Добавлены liveness `/api/v1/health` и проверка PostgreSQL `/api/v1/ready`.
- Добавлены конфигурация окружения, Dockerfile, PostgreSQL Compose-сервис,
  линтеры, статическая проверка типов и тесты.
- Добавлены модели зарегистрированного участника, ролей и множественных
  назначений ролей, а также начальная Alembic-миграция.
- Добавлены Argon2-хеширование паролей, серверные сессии и API регистрации,
  входа, выхода и текущего пользователя.
- Добавлено изменение отображаемого имени в профиле пользователя.
- Добавлена подача и просмотр собственной заявки на роль автора.
- Добавлена административная проверка заявок с автоматическим назначением роли автора.
- Добавлен фундамент публикаций: категории, публикации и локализации RU/EN.
- Добавлено создание черновика публикации в одной из четырёх начальных категорий.
- Документация запуска обновлена: локальный PostgreSQL является основным путём,
  Docker Compose — необязательным.
- Добавлены список собственных публикаций и отправка черновика на проверку.
- Добавлена ручная редакционная очередь, решения редактора и неизменяемые записи
  аудита решений публикации.
- Материал, возвращённый редактором, можно отредактировать и повторно отправить;
  при публикации создаётся сохранённое задание перевода на вторую локаль.
- Аудит редакционного workflow хранит исходное и новое состояние публикации,
  инициатора перехода и обязательную причину решения.
- Добавлен фоновый обработчик заданий перевода с блокировкой от параллельного
  захвата, сохранением локализации и защитой ручной редакторской версии.
- Добавлены подписки участника на авторов: создание, удаление и просмотр списка.
- Добавлена изменяемая оценка опубликованной публикации от 1 до 5.
- Добавлены комментарии и одноуровневые ответы к опубликованным материалам.
- Модератор и администратор могут скрывать и восстанавливать комментарии.
- Публичная страница публикации возвращает готовую локализацию или оригинал,
  пока перевод недоступен; неудачные задания перевода повторяются до трёх раз.
- Добавлена публичная лента опубликованных материалов с пагинацией и fallback на
  оригинальную локализацию, пока перевод не готов.
- Добавлены неизменяемые ревизии оригинального материала: исходное состояние,
  каждая правка, просмотр истории и восстановление версии как новой ревизии.
- Редактор может назначить время публикации; фоновый обработчик публикует
  наступившие материалы и создаёт для них задания перевода.
- Редактор или администратор может архивировать опубликованный материал и
  восстановить его; оба действия записываются в неизменяемый аудит workflow.
- Добавлен каталог игр и подписки участника на игры; каталогом управляет
  контент-менеджер или администратор.
- Участник может пожаловаться на опубликованный материал или видимый комментарий;
  модератор и администратор получают очередь открытых жалоб и фиксируют решение.
- Скрытие и восстановление комментария фиксируются в отдельном неизменяемом
  аудите действий модерации.
- Добавлены обратимые временные блокировки участника с причиной, сроком,
  отзывом активных сессий и неизменяемым аудитом; автор не может оценить свой материал.
- Очередь модератора показывает автора и краткое содержимое цели жалобы, чтобы
  решение и возможная санкция принимались по проверяемому контексту.
- Добавлен асинхронный контур ИИ-проверки публикаций: очередь по ревизиям,
  сохранение объяснимого результата и отдельный API просмотра статуса. Пока
  провайдер не настроен, материалы продолжают идти на ручную проверку.
- Редактор может открыть и вручную отредактировать готовый перевод; такая
  локализация получает происхождение `human` и уже защищена worker’ом от
  последующей автоматической перезаписи.
- Контент-менеджер и администратор могут управлять двуязычными названиями,
  описаниями, цветом, порядком и видимостью категорий; публичный каталог
  возвращает только видимые локализованные категории.
- Материал получил тип (`article`, `review`, `news`, `guide`); у ревью можно
  указать игру из каталога и авторскую оценку. Эти данные входят в ревизии и
  восстанавливаются вместе с версией.
- Редактор, модератор или администратор может подготовить ручной дайджест из
  опубликованных материалов; выбор хранит порядок, а пустой дайджест нельзя
  отправить на проверку.
- Добавлена защищённая недельная UTC-подборка кандидатов журнала с прозрачным
  счётом: средняя оценка и вклад видимых комментариев.
- Добавлена модель выпуска журнала с редактором, UTC-периодом, статусом и
  неизменяемым упорядоченным составом выбранных публикаций после публикации.
- Добавлен API создания выпуска журнала, сохранения его состава и публикации;
  в выпуск можно включить только опубликованные материалы, а после публикации
  его состав нельзя изменить.
- Завершённая ИИ-проверка с решением `pass` автоматически публикует только
  актуальный материал верифицированного автора и идемпотентно ставит перевод в
  очередь; остальные материалы остаются на ручной редакционной проверке.
- Заблокированный участник может подать одно обжалование санкции, подтвердив
  e-mail и пароль без действующей сессии; модератор рассматривает обращение с
  обязательной причиной решения, а одобрение снимает блокировку с аудитом.
- Участник может выгрузить свои профильные данные и собственные материалы с
  локализациями в JSON без пароля и сессионных данных.
- Участник может удалить аккаунт после подтверждения паролем: вход и сессии
  отключаются, идентификаторы псевдонимизируются, а факт удаления сохраняется
  в неизменяемом аудите без удаления редакционных и модерационных следов.
- Публичная карточка материала теперь содержит автора, чтобы читатель мог
  управлять подпиской на него в интерфейсе.
- Добавлено восстановление доступа: одноразовые 30-минутные токены хранятся
  только в хешированном виде, новый пароль отзывает все сессии, а доставка
  ссылки настраивается через SMTP (в local-режиме ссылка выводится в лог).
- Worker ИИ-проверок теперь поддерживает реальный OpenAI-совместимый
  структурированный адаптер: без ключа он по-прежнему безопасно оставляет
  материал на ручной проверке.
- Worker переводов получил OpenAI-совместимый структурированный адаптер; при
  отсутствии настройки исходный материал остаётся доступным, а задание не
  подменяется фиктивным переводом.
- Модератор получил отдельную очередь скрытых комментариев для их явного
  восстановления; действие остаётся в неизменяемом журнале модерации.
- Для регистрации, входа, восстановления доступа, комментариев и жалоб добавлены
  процессные sliding-window лимиты с HTTP 429 и `Retry-After`; production-слой
  может дополнять их распределённым ограничением на edge.
- Sitemap публикует отдельные RU и EN URL материалов, соответствующие
  локализованным canonical/hreflang ссылкам web-приложения.
- Заблокированный участник может подать апелляцию через email и пароль без
  знания технического идентификатора санкции.
- При публикации журнала сохраняется snapshot локализаций и категории каждого
  материала, поэтому готовый выпуск остаётся воспроизводимым после последующих
  изменений исходных публикаций и переводов.
- Администратор может просматривать участников и управлять их ролями; каждое
  назначение или отзыв роли фиксируется в неизменяемом аудите.
- Одобрение заявки автора также создаёт запись в общем аудите выдачи ролей.

### Changed

- Проект переименован в Ion Pulse.
- Корневая рабочая папка переименована из `habr` в `ion-pulse`.
- Локальная папка backend переименована из `habr-clone-api` в `ion-pulse-api`.
- GitHub-репозиторий переименован из `habr-clone-api` в `ion-pulse-api`.

### Removed

- Удалена прежняя реализация backend для разработки новой системы с нуля.

### Pending

- Web-экраны регистрации и входа.
